# Pythonインストーラーを廃止し、skills CLIに一本化する

日付: 2026-11-11。状態: 採用。関連: Issue #20。進め方: パッション駆動（ユーザー指定）、実装は既定サイクル。

置き換える範囲: [three-environment-delivery.md](three-environment-delivery.md)の導入・更新・削除スクリプト、[explicit-package-boundary.md](explicit-package-boundary.md)のインストーラーによる一覧の検査、[skills-cli-update.md](skills-cli-update.md)の「既存installを呼ぶ」「Python方式も残す」。配布一覧方式とスキルの内容は変えない。

## 文脈と仮説

0.3.1でskills CLIによる導入・更新・削除が使えるようになり、導入経路がPythonとCLIの二重になった。管理記録とCLIのlockは独立で、同じ配置を交互に管理できず、説明と保守の両方が重い。CLIだけにすれば、導入の説明が1経路になり、導入物の検証コード（約250行とそのテスト）を持たずに済むと仮定する。

## 決定

- `scripts/install.py`、`scripts/uninstall.py`、`scripts/skill_installation.py`、`scripts/tests/test_installation.py`を削除する。配布一覧から前3つを外す（41→38ファイル）。
- `scripts/build_skills_distribution.py`は一覧のファイルを`skills/martial-arts-research`へコピーするだけにする。管理記録は生成しない。
- インストーラーのテストが担っていた安全網のうち、今も意味があるものだけを`test_skills_distribution.py`へ移す。一覧の禁止名（`feedback/`、隠しパス、`*.local.md`、キャッシュ）と存在確認、検出対象のSKILL.mdが1件であること、コミット済みの生成物が新規生成と一致すること。
- 導入先の手編集保護、置換失敗時の復元、`--user`・`--target`は移さない。CLIの責務であり、配布元はCLIを制御しない。
- 旧配置の移行手順を互換性文書に残す。旧版が必要なら、タグv0.3.1から取得できる。
- 破壊的な廃止のため、版は0.3.1から0.4.0へ上げる。

## 成功指標・撤退条件

CLIがローカルの専用フォルダから38ファイルを導入し、内容が正本と一致すること。全テストが成功すること。公開後にGitHub URLで`add`と`update`を実測する。CLIで導入できない、または導入物が一覧と違う場合は、この変更を戻す。スキルの回答品質は変えないため、内容のA/B評価は対象外。

## 非機能要件と機会費用

依存の追加なし。導入にはNode.jsとネットワークが必要になる。Node.jsのない環境とZIP展開だけの環境は、`install.py`で導入できなくなる。これは受け入れる。手動でフォルダをコピーすれば使え、導入先の保護だけが失われる。Python 3.9以上は実行時のguardにだけ必要。秘密情報・個人情報は生成物に含めない。

## 検証・レビュー

全テスト106件（インストーラーのテスト削除前は120件）とgit diff --checkが成功。skills 1.7.6で、生成した専用フォルダをローカルパスから一時プロジェクトへ導入し、38ファイルが生成物と一致することを確認した。公開後（v0.4.0、2026-11-11）の実測: GitHub URL（`.../tree/main/skills/martial-arts-research`）からの`add`で38ファイル・VERSION 0.4.0が導入され、`update`は「最新」と判定した。この環境の旧0.3.1コピー2件（`.claude`・`.agents`）はバックアップ後に同じURLで入れ直し、生成物とのdiffが一致した。新しい版が出たときの`update`による実更新は、次のリリースで確認する。

他エージェントのレビュー: Codex（サンドボックス内では起動不可）に代え、Antigravity（agy、モデルは指定せず、実際のモデルは応答から確認できない）が差分を読んで3件を指摘した。採用: `rmtree`の`ignore_errors`が削除失敗を隠す点を外した、生成物と配布元のシンボリックリンクをテストで拒否した、READMEの移行手順リンクの重複を除いた。不採用: 生成スクリプト自体へのパス検証と一時ディレクトリ経由の置換。入力は保守者が管理する配布一覧だけで、一覧の不正はテストが拒否し、生成物は`git checkout`で戻せる。実行時の安全網を保守者向けスクリプトに足すと、削除した約250行の複雑さが戻る。
