# 形式保持の最小候補を比較し、差がなければ採用しない

2026-10-31。採用（評価方針）。Issue #4。承認済み改善計画の具体化。

## 仮説・要件・調査

japanese-readability-editorの指定形式保持とmece-cluster-advisorのA/B不採用判断を参考にする。既存のユーザー形式優先を強調する短い指示で、余分な章立てを減らせる可能性がある。descriptionの一律移植や新しい分析軸は採用しない。現状の条件付き読込とrenderを再利用し、候補を本体へ直接適用せず比較する。

## README・モデル

出力は指定形式と、判定を支える情報の双方を保持する。短さは副指標とする。採用候補は形式の事前確認と短縮時の情報保持を末尾に加えるだけ。現状と候補を独立セッションへ同じ資料・依頼で渡す。

## 成功指標と撤退条件

一次指標は6件の指定形式遵守、出典箇所・条件・警告・不足情報・保留判定の保持。候補が形式遵守を1件以上改善し、主要情報に悪化がなく、誤適用を増やさない場合だけ採用する。差なし・悪化・実行不能なら不採用。根拠を削って短くした出力は改善と数えない。

## 実験と費用

既存T03/T06/T09/T10/T14/T24に形式指定を追加し、既存6合成資料を共通利用。Sonnet 5.5 medium、各群1独立セッションに6件をまとめ、ツールなし・各180秒、有効実行は計2回、順序B→Aで固定する。モデルの返却識別子・利用量・入力ハッシュを記録する。温度・乱数seedと順序効果は制御できず、少数の一括評価から一般品質へ外挿しない。
同じ40起動依頼の文面上の適用判断も比較する。description自体は同一。これは製品の自律発見の実測ではなく、#2の製品別評価を代替しない。設定を除外した初回起動はモデル404でAPI利用量0のまま失敗したため無効とし、既存user設定の接続条件を両群へ同じように適用して再実行する。無効試行も非公開で保持する。

## 非機能要件と実装計画

原文・秘密・個人情報を使わず合成資料のみ。候補と基準、実行応答は非公開feedback/に保全し、公開するのは匿名集計と制約のみ。追加課金・依存・ライセンス変更なし。Markdownの指定形式を保持する。
比較をfeedback/run-format-ab.pyで実行し、別エージェントが両群を採点・レビューする。結果をevals/results/format-preservation-ab.mdへ記録しREADMEから参照する。候補不採用ならSKILLの変更・版上げ・Mac再配置は不要。採用時は回帰テストとMac更新を行う。

## 結果

両群とも指定形式6/6、文面上の適用判断40/40。形式改善がなく、採用条件を満たさないため候補を不採用とした。回答文字数は1,311から1,738へ増加した。[評価結果と限界](../evals/results/format-preservation-ab.md)を参照。本体と版は0.2.3を維持する。評価文書だけを配布一覧へ追加し、既存Mac配置にも文書を同期する。

Claude Code Sonnet 5.5 mediumの独立レビューも不採用を支持した。T24の推論悪化、基準側の条件欠落、共通依頼による効果の見えにくさ、手動非盲検採点、実機起動ではない限界を結果へ反映した。一回限りの非公開評価のため、汎用ランナーや再試行機構は追加しない。返却モデルと利用量は生応答に保存されており、メタデータファイル単体の不足は記録の不存在と区別する。
