# WikiSkill成果物比較の手順

この評価は、スキル更新の**改訂本文**と通常の研究・問題報告を、共通正本から作成する比較である。既存の短い事実回答評価と区別する。採否と効果の結論は結果記録にのみ記す。

## 課題と候補

合成82課題は、開発6更新・4通常、確認48更新・24通常。公開資料から候補を見せない生成手順で作成し、確認実行前に固定した。課題の観察は実利用者の報告ではない。C-N06のユーザ名・端末パスも架空の文字列である。意味上の類似や同一領域内の相関は残り、全実務の無作為標本とは呼ばない。

- A: 共通の実行指示だけ。
- B1: 観察・仮説・適用条件・反証を分ける保守ガイドを追加。
- B2: B1に少数の正本索引を追加。
- B3 v2: 更新時にだけ保守ガイドと索引を読む入口。旧B3の発火不足を開発段階で一回だけ修正したもの。

共通指示にはSKILL.md、docs/feedback.md、docs/templates/problem-report.mdの全文を含む。これらを再読しなくても参照済みとする。その他の正本は検索・読取専用MCPで取得する。maintenanceはB3だけに直接読取で提供し、検索からは除く。索引だけを独立した正本の証拠にしない。

## 実行の準備

全試行の入力とログはGit除外されたfeedback/に置く。認証設定や秘密は記録しない。次はモデルを呼ばずに入力を凍結する。

```sh
python3 scripts/prepare_wikiskill_artifacts.py --out feedback/artifact-freeze
```

そのcases-all.jsonから**1課題だけ**をcases配列へ取り出したJSONをfeedback/one-case.jsonに保存し、次で1割付けを実行できる。

```sh
python3 scripts/evaluate_wikiskill_artifacts.py --frozen feedback/artifact-freeze --cases feedback/one-case.json --arm A --out feedback/one-call
```

この経路はローカルのClaude Code CLIと既存の接続設定を使用する。CLI実行ファイルは/opt/homebrew/bin/claude、指定・検証する報告モデルはclaude-sonnet-5-5、effortはmedium。MCP以外のツール、外部MCP、skills、slash commandsを許可しない。組込みplugins/agentsは記録する。プロキシ内部の処理や、3製品でのネイティブなスキル発見・起動を実証する試験ではない。

## 検証と判定

課題ごとに新規セッションで4腕を固定seedの順序で実行する。確認は累積16/32/48更新と8/16/24通常の3段階。最大24ターン・300秒。未完成回答と時間切れは割付けの分母に残し、API上限・輸送障害は別記録にして停止する。保存済み成功呼出を取り直さない。

モデル名・ツール一覧・CLIとサーバ監査・入力hash・最終契約・引用可能性を検査する。採点者2系統には腕名、system、監査を渡さず、原資料と観察と成果物を渡す。[固定した採点指示](fixtures/wikiskill-artifacts/grading-instructions.md)を共通に用いる。本文から処置を推測する可能性は残る。対照での校正と不一致の根拠裁定を行い、開発結果を確認統計へ混ぜない。

品質差は対応する課題の勝ち/負け率から保守的な二項境界を構成し、3候補×3段階×2率×2方向の36境界へ総α=.05を配分する。実務上の便益は15ポイント改善を目安とする。効率経路は品質下限−15ポイント以上、重要な後退なしを前提に、返却文字数15%以上減、時間20%以上減、報告総トークン増10%以内を同時に求める。資源比は完全ペアだけなので、未完成数と欠落ペア数を併記し、欠落のある腕を効率だけで採用しない。

B3は全更新で両資料の読取、通常で非発火、B2比の時間・トークン増10%以内も必要。有限標本で不確実性が残る場合は不足を記し、導入の見送りを「効果なしの証明」と呼ばない。詳しい仮説・撤退基準は[ADR](../adr/wikiskill-sufficient-validation.md)を参照。
